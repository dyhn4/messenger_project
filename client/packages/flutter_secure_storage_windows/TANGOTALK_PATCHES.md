# TangoTalk에서 고친 점 (flutter_secure_storage_windows 3.1.2 기준)

pub.dev의 `flutter_secure_storage_windows` 3.1.2를 그대로 복사한 뒤 `lib/src/flutter_secure_storage_windows_ffi.dart`만
고쳤다. 앱은 `client/pubspec.yaml`의 `dependency_overrides`로 이 사본을 쓴다. 저장 형식(앱 데이터 폴더의
`flutter_secure_storage.dat` — DPAPI로 암호화한 JSON 한 덩어리)은 그대로라, 이전 버전 앱이 저장한 값을 그대로 읽는다.

원래 구현은 값 하나를 쓸 때마다 파일 전체를 읽고 고쳐 **그 자리에 덮어썼다**. 그래서 다음 문제가 있었다.

1. **쓰는 도중 끊기면 파일이 깨짐** — 앱이 강제 종료되거나 전원이 나가면 반쯤 쓴 파일이 남는다.
2. **읽지 못한 파일을 지움** — 복호화·JSON 해석에 실패하면 파일을 지웠다. 기기 신원키와 모든 비밀 대화 키가 함께
   사라져, 그 PC의 비밀 대화를 모두 새로 시작해야 했다.
3. **작업이 겹치면 변경이 사라짐** — 읽고-고치고-쓰기 사이에 다른 작업이 끼면 늦게 끝난 쪽이 먼저 끝난 쪽의 변경을
   덮어썼다(비밀 대화 저장소와 기기 신원은 서로 다른 곳에서 저장소를 쓴다).

고친 점:

- **통째로 바꿔 끼우기** — 새 내용을 `flutter_secure_storage.dat.tmp<프로세스 id>`에 쓰고 디스크까지 내린(flush) 뒤
  `MoveFileEx(MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)`로 원래 파일 자리에 옮긴다. 원래 파일은 언제나 예전
  내용이거나 새 내용 중 하나다(전원이 나가면 마지막 바꿔 끼우기가 되돌아가 한 단계 전 내용일 수는 있다 — 깨지지는 않는다).
  백신·색인 프로그램이 잠깐 파일을 잡고 있으면 몇 번 다시 해 본다. 옮기기에 실패하면 오류 번호를 못 읽었어도 실패로 본다.
- **잠깐 못 읽은 것을 빈 저장소로 보지 않음** — 원래 구현은 파일을 읽다 실패하면(다른 프로그램이 잡고 있음 등) 빈 저장소로
  보았고, 그 직후의 쓰기가 값 하나만 든 파일로 바꿔 끼워 모든 키를 지웠다. 이제 파일이 정말 없을 때만 빈 저장소로 보고, 아니면
  몇 번 다시 읽은 뒤 그 작업을 실패로 끝낸다.
- **읽지 못한 파일은 남김** — 지우지 않고 `flutter_secure_storage.dat.unreadable`로 옮긴다. 이미 있으면(처음 남긴 것에 원래
  키가 들어 있다) 덮어쓰지 않고 `….unreadable-<시각>`으로 남긴다. 일시적인 문제(Windows 사용자 키를 잠깐 못 씀 등)였다면 이
  파일로 되살릴 수 있다(앱을 끄고 이름을 `flutter_secure_storage.dat`로 바꿈). 옮기지 못할 때만 예전처럼 지운다.
- **한 번에 하나씩** — 이 프로세스 안의 모든 저장소 작업(읽기·쓰기·지우기)을 한 줄로 세운다. 앱을 두 개 띄우면 서로의
  변경을 덮어쓸 수 있는 것은 원래와 같다(파일이 깨지지는 않는다).
- 테스트용으로 파일 위치를 바꿀 수 있게 `DpapiJsonFileMapStorage(filePath: …)`를 더했다.

검증: `client/test/secure_storage_windows_patch_test.dart`(Windows에서만 돈다 — 실제 DPAPI로 저장·읽기, 남은 임시 파일,
읽지 못한 파일 옮기기, 겹친 쓰기).

플러그인을 새 버전으로 올릴 때는 새 버전이 같은 문제를 고쳤는지 보고, 아니면 이 고친 점을 다시 옮긴다.
