TangoTalk 도움말

서버 관리

TangoTalk 서버를 설치하고 운영하는 서버 운영자를 위한 안내입니다. 서버 PC에 프로그램을 설치하는 방법, 시작 메뉴에 생기는 관리 도구, 회사 밖에서 접속하게 하는 방법(외부 접속 주소 · DuckDNS · 웹 앱 주소), 앱의 서버 관리 화면을 차례로 설명합니다. 메신저를 쓰기만 한다면 이 페이지는 몰라도 됩니다.

1서버 프로그램 설치

설치 프로그램 하나(tangotalk-server-setup.exe)가 서버 프로그램, 데이터베이스(PostgreSQL), 화상회의 서버까지 한 번에 설치합니다. 데이터베이스 비밀번호나 암호화 키는 설치 프로그램이 스스로 만들어 안에서만 씁니다. 따로 정하거나 적어 둘 필요가 없습니다.

설치 전에 준비할 것

  • 늘 켜 둘 Windows PC 한 대 — 서버가 꺼지면 아무도 메신저를 쓸 수 없습니다. 절전 모드로 들어가지 않게 해 두세요.

  • 그 PC의 관리자 계정 — 설치와 모든 관리 도구가 관리자 권한을 씁니다.

  • 공유기에서 이 PC의 사내 IP를 고정해 두기(권장) — 나중에 회사 밖 접속을 위해 포트포워딩을 하면 이 IP로 보내기 때문입니다.

  • 설치 파일 tangotalk-server-setup.exe — USB나 사내 공유 폴더로 서버 PC에 옮겨 둡니다.

설치하기

  1. tangotalk-server-setup.exe를 실행하고, 관리자 권한 확인 창에서 예를 누릅니다. "Windows의 PC 보호" 창이 뜨면 추가 정보 › 실행을 누릅니다.

  2. 설치 경로를 고릅니다. 기본값 C:\TangoTalk-Server를 그대로 써도 되고, 다른 드라이브라면 그 아래 전용 폴더(예: E:\TangoTalk-Server)를 고르세요. 드라이브 맨 위나 Program Files 같은 공용 폴더는 피합니다.

  3. 서버 실행 방식을 고릅니다.

    방식설명
    백그라운드 Windows 서비스로 등록(권장)PC를 켜면 서버가 저절로 시작하고 창이 없습니다. 로그아웃해도 계속 돕니다.
    콘솔 창으로 실행시작 메뉴 서버 콘솔로 실행으로 띄운 창에서 서버가 돕니다. 창을 닫으면 서버도 꺼집니다.

  4. 설치를 누릅니다. 데이터베이스를 처음 설치하느라 몇 분 걸릴 수 있습니다. 중간에 검은 창이 잠깐 떴다 사라져도 그대로 기다리세요.

  5. 마침을 누르면 끝입니다. 설치 프로그램이 이 PC의 방화벽 규칙도 만들어 두므로, 같은 사내망의 PC · 휴대폰은 바로 접속할 수 있습니다.

설치되는 것

서버 프로그램(Node.js), 이 서버 전용 PostgreSQL(이 PC의 다른 PostgreSQL과 겹치지 않게 전용 포트 55432), 화상회의 서버(LiveKit), 시작 메뉴의 TangoTalk Server 관리 도구(2장)입니다. 메신저는 기본으로 3000번 포트(HTTPS), 새 기기 연결과 초대 안내 페이지는 3001번 포트를 씁니다.

설치 확인과 첫 운영자 계정

  1. 서버 PC의 브라우저에서 https://localhost:3000/health를 엽니다. {"ok":true}가 보이면 서버가 정상입니다. "안전하지 않음" 경고가 뜨면 고급 › 계속으로 넘어가면 됩니다(서버가 직접 만든 인증서라서 뜨는 경고입니다).

  2. 내 PC나 휴대폰에 앱을 설치하고 연결합니다. 시작 메뉴 새 기기 페어링 코드 발급(아래)으로 4자리 코드를 받아, 앱의 서버 연결 화면에 서버 PC의 주소(예: https://192.168.0.10:3000)와 함께 넣습니다.

  3. 앱에서 회원가입을 합니다. 계정이 하나도 없는 서버의 첫 가입자는 저절로 관리자 등급 + 서버 운영자가 됩니다. 그래서 서버를 설치한 사람이 가장 먼저 가입하세요.

  4. 가입한 뒤 ☰ 메뉴에 서버 관리가 보이면 준비가 끝났습니다(7장). 팀을 만들고, 직원들에게 초대 링크를 보내세요(메신저 이용법 › 초대 링크 보내기).

설치 폴더는 관리자 전용

설치 폴더에는 데이터베이스, 비밀값, 인증서, 백업, 첨부파일이 들어 있습니다. 그래서 설치 프로그램이 이 폴더를 SYSTEM과 관리자(Administrators)만 열고 고칠 수 있게 잠급니다. 다른 Windows 계정은 시작 메뉴 바로가기와 안내문만 열 수 있습니다.

  • 설정 파일(server\.env)이나 로그(server\service-err.log)를 보려면 메모장을 관리자 권한으로 실행한 뒤 파일 › 열기로 엽니다.

  • 탐색기로 이 폴더에 파일을 넣을 때 "관리자 권한이 필요합니다" 창이 뜨면 계속을 누릅니다.

  • 시작 메뉴의 관리 도구는 실행할 때마다 관리자 권한 확인 창을 띄웁니다. 예를 누르세요 (관리자가 아닌 계정이면 관리자 계정 암호가 필요합니다).

다시 설치 · 제거할 때

  • 같은 경로로 다시 설치하면 데이터베이스 · 설정 · 첨부파일 · 인증서는 그대로 두고 프로그램 파일만 새로 바꿉니다. 새 설치 프로그램이 나왔을 때나 프로그램 파일이 망가졌을 때 씁니다.

  • 설치 프로그램이 "이전 TangoTalk 서버 설치나 이 PC의 관리자 권한으로 만든 폴더인지 확인되지 않았습니다"라며 멈추면 그 폴더를 바로 지우지 마세요. 예전 서버의 데이터가 들어 있을 수 있습니다. 내용을 확인하고 필요한 것을 옮긴 뒤 새 폴더를 고르세요.

  • 서버를 걷어내는 방법은 초기화 · 완전 삭제 · 제거에서 고릅니다. 셋이 지우는 범위가 다릅니다.

2시작 메뉴 관리 도구

설치가 끝나면 시작 메뉴에 TangoTalk Server 그룹이 생깁니다. 서버 운영에 필요한 일은 대부분 여기서 합니다.

새 기기 페어링 코드 발급

앱은 처음 연결할 때 이 서버가 진짜 우리 서버인지 코드로 확인합니다. 초대 링크로 연결하면 코드가 저절로 들어가지만, 직접 연결할 때는 이 코드가 필요합니다.

  1. 시작 메뉴 새 기기 페어링 코드 발급을 누르고 관리자 권한 확인 창에서 예를 누릅니다.

  2. 새 기기 연결 코드: 1234처럼 4자리 코드가 뜹니다. 5분 동안 한 번만 쓸 수 있습니다.

  3. 앱의 서버 주소 변경(처음 켰다면 서버 연결) 화면에 서버 주소와 이 코드를 넣고 연결을 누릅니다.

"페어링 시도가 너무 많습니다"가 나오면

코드 맞혀 보기를 막으려고, 같은 곳에서 15분 동안 연결 시도를 너무 많이 하면 잠시 막습니다. 안내된 시간만큼 기다리거나, 급하면 서버 재시작을 하면 바로 풀립니다. 코드는 5분짜리 1회용이니, 실패했으면 새 코드를 받아 한 번에 입력하세요.

서버 재시작 · 서버 콘솔로 실행

  • 서버 재시작은 프로그램이나 데이터는 건드리지 않고 서버만 다시 시작합니다. 다시 켜진 뒤 서버가 정상이 아니면 오류 기록을 지금 메모장으로 열까요?라고 묻습니다. Y를 누르면 오류 내용(service-err.log)을 바로 볼 수 있습니다.

  • 서버 콘솔로 실행은 콘솔 창 방식으로 설치했을 때만 있습니다. 창을 닫으면 서버도 꺼지니, 쓰는 동안은 창을 열어 두세요.

첨부파일 저장소

대화방에 올린 사진 · 파일은 기본으로 설치 폴더 안(server\uploads)에 저장됩니다. 서버 PC의 디스크가 부족하면 다른 곳으로 옮길 수 있습니다.

  1. 시작 메뉴 첨부파일 저장소를 엽니다. 지금 저장 위치가 보입니다.

  2. 찾아보기...로 새 폴더를 고르거나, NAS · 다른 PC의 공유 폴더라면 \\서버\공유\폴더 형식으로 직접 입력합니다. 드라이브 맨 위나 Windows · 사용자 폴더처럼 다른 것과 함께 쓰는 폴더는 받지 않으니, 전용 폴더를 새로 만들어 고르세요.

  3. 적용을 누릅니다. 이미 있는 파일을 새 위치로 옮길지 묻고, 설정을 바꾼 뒤 서버를 다시 시작합니다.

NAS는 접근 권한을 직접 막으세요

이 PC의 로컬 폴더는 관리자 전용으로 잠가 주지만, NAS나 공유 폴더는 이 PC가 잠글 수 없습니다. NAS 설정에서 이 서버 PC만 접근하게 제한하세요.

백업 · 복원

서버는 관리자 콘솔의 백업 탭에서 백업 암호를 정해 두면 매일 스스로 백업합니다. 시작 메뉴의 두 도구는 "지금 한 번 더 백업"과 "되돌리기"를 할 때 씁니다.

  • 백업은 관리자 콘솔의 지금 백업과 같은 전체 백업(데이터베이스 · 서버 설정 · 인증서, 외부 백업 위치를 정했으면 첨부파일까지)을 설치 폴더\backups\tangotalk_날짜_시각 폴더로 만듭니다. 서버를 멈추지 않으니 언제든 눌러도 됩니다. 백업 암호를 아직 정하지 않았으면 예전처럼 데이터베이스만 messenger_날짜시각.dump 파일로 저장합니다.

  • 복원은 백업을 골라 그 시점으로 되돌립니다. 전체 백업은 백업 폴더 안의 manifest.json을, 예전 백업은 .dump 파일을 고릅니다. 지금 데이터는 백업 내용으로 바뀌므로 서버 운영자 아이디 · 비밀번호를 확인하고(전체 백업은 백업 암호도), RESTORE를 정확히 입력해야 진행됩니다. 복원하는 동안은 서버가 잠시 멈추고, 지금 데이터베이스와 설정은 바꾸기 전에 backups 폴더에 따로 남깁니다.

서버 PC가 고장 났을 때(새 PC로 되살리기)

  1. 새 PC에 TangoTalk 서버를 설치합니다(1장). 가입은 하지 않습니다.

  2. 외장 드라이브를 꽂거나 NAS에 연결한 뒤 시작 메뉴 복원을 엽니다.

  3. 외부 백업 위치의 TangoTalk-Backup\tangotalk_날짜_시각 폴더(가장 최근 것)에서 manifest.json을 고릅니다. 회원이 없는 새 서버라 운영자 확인은 건너뛰고 백업 암호만 묻습니다. 첨부파일도 복원할지 물으면 Y.

  4. 끝나면 회원 · 대화 · 설정 · 첨부파일과 서버 인증서가 그대로 돌아옵니다. 서버 PC의 IP가 바뀌었으면 공유기 포트포워딩을 새 PC로 바꾸고, 사내 와이파이에서만 쓰던 기기는 새 주소로 다시 연결합니다.

백업 암호를 잃어버리면 복원할 수 없습니다

백업은 백업 암호로 암호화돼 있어 NAS나 외장 드라이브에 두어도 암호 없이는 열 수 없습니다. 그 대신 암호를 잊으면 아무도 열 수 없으니, 서버 PC가 아닌 안전한 곳에 적어 두세요. 예전 방식의 .dump 백업은 암호화돼 있지 않으니 아무나 열 수 없는 곳에 두세요.

초기화 · 완전 삭제 · 제거

바로가기지우는 것남는 것
DB 데이터 초기화회원 · 팀 · 메시지 · 댓글 · 첨부파일 등 데이터서버 프로그램 · 설정 · 인증서(바로 빈 서버로 다시 쓸 수 있고, 처음 가입하는 사람이 새 운영자가 됩니다)

초기화와 완전 삭제는 되돌릴 수 없어서, 먼저 서버 운영자 아이디 · 비밀번호를 확인한 뒤 각각 RESET · DELETE를 정확히 입력해야 진행됩니다. 이 PC 앞에 앉을 수 있다는 것만으로는 데이터를 지울 수 없게 한 것입니다.

완전 삭제한 뒤 예전 백업을 복원하려면

전체 백업(tangotalk_날짜_시각 폴더)에는 암호화 키가 들어 있어 백업 암호만 있으면 됩니다. 예전 방식의 .dump 백업을 복원할 생각이면 완전 삭제 전에 server\.db-encryption-key 파일을 안전한 곳에 복사해 두세요. 이 키가 없으면 복원한 데이터 속 암호화된 이메일 등을 읽을 수 없습니다.

3서버 업데이트

새 버전이 나오면 업데이트 파일(zip)을 받아 적용합니다. 데이터베이스의 기존 데이터는 그대로 두고, 프로그램과 데이터베이스 구조만 바꿉니다.

업데이트 파일 적용

  1. 받은 업데이트 zip 파일을 서버 PC에 둡니다(압축은 풀지 않습니다).

  2. 시작 메뉴 서버 업데이트를 열고 찾아보기...로 zip 파일을 고릅니다.

  3. 업데이트 시작을 누릅니다. 아래 다섯 단계가 차례로 진행되고 창에 기록이 나옵니다.

    단계하는 일
    1/5설치 폴더 접근 권한 점검(파일이 많아 1~2분 걸릴 수 있습니다)
    2/5새 프로그램 파일 적용
    3/5필요한 부품(패키지) 설치
    4/5데이터베이스 구조 반영 — 기존 데이터는 그대로 두고 새로 생긴 구조만 더합니다
    5/5서버 재시작

  4. 완료 창이 뜨면 끝입니다. 앱을 쓰던 사람들은 잠시 끊겼다가 저절로 다시 연결됩니다.

중간에 실패했다면 끝까지 다시 하세요

3/5 이후에 실패하면 새 프로그램 파일만 들어가고 데이터베이스 구조가 반영되지 않은 상태로 남습니다. 이대로 서버가 다시 켜지면 관리자 콘솔 일부나 알림이 동작하지 않을 수 있습니다. 원인을 해결한 뒤(문제가 생겼을 때) 같은 zip으로 서버 업데이트를 다시 실행하세요. 같은 파일로 여러 번 적용해도 괜찮습니다.

설치 프로그램을 다시 실행할 때

업데이트 zip은 서버 프로그램만 바꿉니다. 시작 메뉴의 관리 도구와 설치 과정이 바뀐 버전이 나오면, 새 tangotalk-server-setup.exe를 같은 설치 경로로 한 번 다시 실행해야 새 관리 도구가 들어갑니다. 데이터베이스 · 설정 · 첨부파일 · 인증서는 그대로 이어집니다. 다시 설치한 뒤에는 그 버전의 업데이트 zip을 이어서 적용하세요.

앱 설치 파일 올리기

초대 안내 페이지의 Windows용 다운로드 · Android용 다운로드와 앱의 업데이트 알림은 서버의 설치 폴더\server\releases 폴더에 있는 파일을 씁니다.

파일쓰이는 곳
client-windows-setup.exePC 앱 설치 파일 — 초대 페이지 다운로드, PC 앱 업데이트
client-android.apk안드로이드 앱 설치 파일 — 초대 페이지 다운로드, 안드로이드 앱 업데이트
version.json지금 배포한 앱 버전 — 이 값이 앱보다 높으면 앱에 업데이트 알림이 뜹니다

새 앱 버전을 받았다면 이 세 파일을 그 폴더에 넣습니다(관리자 권한 필요). 서버를 다시 시작하지 않아도, 켜져 있는 앱에 바로 업데이트 알림이 갑니다. 이 폴더가 비어 있으면 초대 페이지에서 다운로드를 눌렀을 때 아직 배포된 빌드가 없습니다.가 나옵니다.

4사내 와이파이 밖에서 접속하게 하기

처음 설치한 서버는 회사 안(같은 공유기)에서만 접속됩니다. 직원들이 집이나 외근지에서 LTE/5G로도 메신저를 쓰게 하려면 아래 세 가지를 준비합니다. 사용하는 사람 쪽에서 할 일은 거의 없습니다(메신저 이용법 › 사내 와이파이 밖에서 쓰기).

무엇을 준비하나요

  1. 밖에서 부를 이름(도메인) — 회사 인터넷의 공인 IP는 바뀔 수 있어서, 그 IP를 따라다니는 이름을 만듭니다. 공유기의 DDNS(예: xxx.iptime.org)를 켜거나, 무료 DuckDNS(예: xxx.duckdns.org)를 씁니다. 고정 공인 IP가 있다면 IP를 그대로 써도 됩니다.

  2. 공유기 포트포워딩 — 밖에서 들어온 연결을 서버 PC로 보내도록 공유기에 적어 둡니다(아래).

  3. 외부 접속 주소 — 그 이름(과 포트)을 서버에 알려 줍니다(아래).

공유기 포트포워딩

공유기 관리 화면(예: iptime은 고급 설정 › NAT/라우터 관리 › 포트포워드 설정)에서 아래 포트를 서버 PC의 사내 IP로 보냅니다. 표의 포트는 기본값입니다.

용도외부 포트 → 서버 PC 포트꼭 필요한가요
메신저 · 새 기기 연결 · 화상회의 신호TCP 3000 → 3000필수
화상회의 영상 · 음성UDP 50000~60000 → 같은 번호, TCP 7881 → 7881밖에서 화상회의를 쓰려면
초대 안내 페이지 · 설치 파일 받기TCP 3001 → 3001(같은 번호로)밖에서 초대 링크를 열게 하려면
웹 앱 주소(정식 인증서)TCP 443 → 443, TCP 80 → 806장을 켤 때만

외부 3000번을 이미 다른 프로그램이 쓰고 있다면

외부 포트와 서버 PC 포트는 달라도 됩니다. 예를 들어 외부 TCP 3010 → 서버 PC 3000으로 포워딩하고, 외부 접속 주소에 xxx.duckdns.org:3010처럼 외부 포트를 붙여 넣으면 됩니다. 다만 초대 안내 페이지 주소는 서버 PC의 3001번을 그대로 쓰므로, 그 포트는 외부도 같은 번호(3001 → 3001)로 열어야 합니다.

외부 접속 주소 넣기

  1. 시작 메뉴 외부 접속 주소를 엽니다.

  2. 칸에 밖에서 부를 이름을 넣습니다. 예: xxx.duckdns.org. 공유기의 외부 포트가 서버 포트(3000)와 다르면 xxx.duckdns.org:3010처럼 "주소:포트"로 넣습니다. 창 아래쪽에 공유기에 포워딩할 포트가 안내됩니다.

  3. 적용을 누릅니다. 서버 인증서에 이 주소가 없으면 인증서를 새로 만든다는 확인 창이 뜹니다. 예를 누르면 설정을 저장하고 서버를 다시 시작합니다. 적용됐습니다. 외부 접속 주소: https://…가 나오면 끝입니다.

이미 연결해 둔 앱은 어떻게 되나요

서버는 같은 키로 인증서를 다시 만들기 때문에, 최신 버전 앱은 다시 연결하지 않아도 그대로 접속됩니다. 그보다 예전 버전의 앱만 한 번 다시 연결해야 하니, 외부 접속 주소를 넣기 전에 모든 기기의 앱을 최신으로 업데이트해 두세요.

외부 접속을 끄려면 칸을 비우고 적용을 누릅니다. 공유기의 포트포워딩도 함께 지우세요.

설정한 뒤 확인할 것

  • 회사 와이파이에서 앱을 한 번 켜 두면 앱이 외부 주소를 받아 저장하고, 그 뒤로는 밖에서 저절로 외부 주소로 연결합니다.

  • 휴대폰의 와이파이를 끄고 LTE/5G로 앱을 켜서 연결되는지 확인해 보세요.

  • 초대 링크를 새로 만들면 사내 와이파이 밖(LTE/5G)에서 주소가 함께 복사됩니다 (메신저 이용법 › 초대 링크 보내기).

  • 공인 IP가 바뀌어도 이름이 서버를 가리키도록 DDNS 갱신을 켜 두세요(5장).

5DuckDNS 도메인

DuckDNS(duckdns.org)는 xxx.duckdns.org 같은 이름을 무료로 주고, 회사의 공인 IP가 바뀌면 그 이름도 따라 바꿔 주는 서비스입니다. 공유기의 DDNS(iptime 등)를 쓴다면 이 장은 건너뛰어도 됩니다.

도메인 만들기

  1. 브라우저에서 https://www.duckdns.org에 들어가 구글 등 계정으로 로그인합니다.

  2. 화면의 token 값을 확인해 둡니다. 이 값은 그 DuckDNS 계정의 모든 도메인을 바꿀 수 있는 비밀값이니 다른 사람에게 보내지 마세요.

  3. sub domain 칸에 원하는 이름(예: mycompany-chat)을 넣고 add domain을 누릅니다. 이제 mycompany-chat.duckdns.org가 지금 접속한 곳의 공인 IP를 가리킵니다. 회사 공유기 뒤에서 만들었다면 이미 회사 공인 IP로 맞춰져 있습니다.

도메인은 계정당 여러 개 만들 수 있어요

개발용 서버처럼 서버가 둘이면 이름을 따로 만들어 각자 쓰세요. 같은 이름을 두 서버가 함께 쓰면 연결이 엉뚱한 서버로 갈 수 있습니다.

서버가 자동으로 갱신하게 하기

공인 IP가 바뀌면 DuckDNS에 새 IP를 알려야 합니다. 서버가 켜져 있는 동안 5분마다 대신 알려 주도록 설정합니다.

  1. 앱에서 ☰ › 서버 관리 › DDNS 탭을 엽니다.

  2. DuckDNS 도메인 칸에 이름을 넣습니다(예: mycompany-chat.duckdns.org 또는 mycompany-chat, 여러 개는 쉼표로, 5개까지).

  3. 토큰 칸에 DuckDNS의 token을 붙여 넣습니다.

  4. 자동 갱신 사용을 켜고 저장을 누릅니다. 바로 한 번 갱신해 보고 결과를 알려 줍니다.

  5. 위쪽 DuckDNS 자동 갱신 카드가 정상이고 mycompany-chat.duckdns.org → 공인 IP, 마지막 성공 · 다음 갱신 시각이 보이면 끝입니다. 카드 오른쪽 위 새로고침 단추(지금 갱신)로 언제든 바로 갱신할 수 있습니다.

토큰은 다시 보이지 않아요

저장한 토큰은 암호화해 두고 화면에는 토큰: 설정됨으로만 보여 줍니다. 바꿀 때만 새로 넣고, 칸을 비워 두고 저장하면 저장된 토큰이 그대로입니다. 토큰 지우기를 하거나 도메인을 비우면 자동 갱신이 꺼집니다.

"실패"로 나오면

DuckDNS가 갱신을 거절했습니다는 도메인 이름이 그 토큰의 계정 것이 아니거나 토큰이 틀렸다는 뜻입니다. duckdns.org에서 이름과 token을 다시 확인하세요. DuckDNS에 연결하지 못했습니다는 서버 PC의 인터넷 연결 문제입니다. 서버가 꺼져 있는 동안은 갱신하지 않습니다.

예전 갱신 작업 끄기

예전에 서버 PC의 작업 스케줄러(PowerShell 등)로 DuckDNS를 갱신하고 있었다면, DDNS 탭이 정상으로 바뀐 것을 확인한 뒤 그 작업은 꺼도 됩니다. 그 도메인을 메신저 말고 다른 서비스도 쓴다면 작업을 남겨 두세요(둘이 함께 돌아도 같은 IP를 알릴 뿐이라 문제없습니다).

  1. 시작 메뉴에서 작업 스케줄러를 엽니다.

  2. 왼쪽 작업 스케줄러 라이브러리에서 DuckDNS를 갱신하던 작업을 찾습니다(작업을 고르고 아래 동작 탭에서 실행하는 파일을 확인할 수 있습니다).

  3. 작업을 오른쪽 클릭하고 사용 안 함을 누릅니다. 그 작업이 실행하던 스크립트 파일에 토큰이 적혀 있다면 그 파일도 지우세요.

6웹 앱 주소(정식 인증서)

아이폰에는 설치형 앱이 없어서 Safari로 웹 앱을 씁니다. 웹 앱을 경고 없이 열고, 홈 화면에 추가해 알림까지 받으려면 브라우저가 믿는 정식 인증서가 필요합니다. 서버가 Let's Encrypt(무료 공인 인증 기관)에서 인증서를 스스로 받고 갱신합니다.

왜 필요한가요

  • PC · 안드로이드 앱은 서버가 직접 만든 인증서를 그대로 씁니다. 그래서 이 설정이 없어도 잘 동작하고, 켜도 다시 연결할 필요가 없습니다.

  • 브라우저는 직접 만든 인증서에 "안전하지 않음" 경고를 띄우고, 아이폰은 그런 사이트에서 웹 앱 알림을 쓸 수 없습니다.

  • 켜면 같은 메신저가 웹 전용 포트(기본 443)에서 정식 인증서로 한 번 더 열립니다. 아이폰뿐 아니라 PC · 안드로이드 브라우저에서도 https://도메인으로 설치 없이 쓸 수 있습니다.

설정하기

  1. 도메인 준비 — 공유기 DDNS나 DuckDNS 이름을 준비합니다. 외부 접속 주소에 쓴 이름과 같아도 됩니다.

  2. 시작 메뉴 웹 앱 주소(정식 인증서)를 열고 칸을 채웁니다.

    칸넣을 값
    도메인예: xxx.duckdns.org — https://나 포트 없이 이름만. IP 주소는 안 됩니다.
    웹 HTTPS 포트기본 443. 이 PC에서 IIS 등이 443을 쓰고 있으면 다른 번호(예: 8443)
    인증용 HTTP 포트기본 80. 0으로 두면 쓰지 않고 443으로만 확인합니다.
    이메일(선택)Let's Encrypt 연락처 — 비워도 됩니다.
    시험 발급처음에는 켜 두기를 권합니다(아래 발급 확인하기).

  3. 적용을 누릅니다. 설정 저장, 이 PC의 방화벽 규칙, 서버 재시작까지 해 줍니다. 이 PC의 다른 프로그램이 그 포트를 쓰고 있거나 도메인을 찾을 수 없으면 적용 전에 알려 줍니다.

  4. 공유기 포트포워딩 — 외부 TCP 443 → 이 PC의 웹 HTTPS 포트, 외부 TCP 80 → 이 PC의 인증용 HTTP 포트를 엽니다. 웹 HTTPS 포트를 443이 아닌 번호로 했다면 외부도 그 번호로 열고, 아이폰 사용자가 여는 주소에 그 번호가 붙습니다(예: https://xxx.duckdns.org:8443).

발급 확인하기

  1. 시험 발급을 켜고 적용했다면 1~2분 뒤 인증서 확인을 누릅니다. 시험용 인증서가 보이면 포트포워딩이 맞다는 뜻입니다. (시험용 인증서는 정식 발급 한도를 쓰지 않는 대신 아이폰에서는 쓸 수 없습니다.)

  2. 시험 발급을 끄고 다시 적용합니다. 이번에는 바로 정식 인증서를 받으러 갑니다.

  3. 1~2분 뒤 인증서 확인이나 앱의 서버 관리 › DDNS 탭 아래쪽 웹 앱 주소(정식 인증서) 카드에서 사용 중과 만료일을 확인합니다. 만료 전에 서버가 알아서 갱신합니다.

  4. 아이폰 사용자에게 Safari로 https://도메인을 열어 로그인하고, 공유 단추 › 홈 화면에 추가 한 뒤 홈 화면 아이콘에서 알림을 켜라고 안내합니다(메신저 이용법 › 아이폰에서는 웹 앱으로). 초대 링크 안내 페이지에도 웹 앱 열기 버튼이 저절로 생깁니다.

끄려면 같은 창의 끄기를 누릅니다(이 PC의 방화벽 규칙도 지웁니다). 공유기의 443 · 80 포트포워딩도 지우세요.

발급이 안 될 때

  • 발급 실패가 나오면 카드에 이유와 다음 시도 시각이 나옵니다. 서버는 1시간부터 점점 간격을 늘려(최대 하루) 알아서 다시 시도하고, 서버를 다시 시작해도 그 시각 전에는 다시 묻지 않습니다.

  • 포트포워딩 — 외부 443(또는 80)이 이 PC로 오지 않으면 실패합니다. 시험 발급으로 먼저 확인하세요. 통신사가 80을 막아도 443으로 받을 수 있습니다.

  • iptime.org 이름 — Let's Encrypt는 iptime.org 아래 이름을 모두 도메인 하나로 세서, 모든 iptime DDNS 사용자가 "7일에 새 인증서 50개" 한도를 함께 씁니다. 한도 초과로 실패하면 안내된 시각까지 기다리거나 DuckDNS · 회사 도메인 이름을 쓰세요. 한 번 받은 인증서의 갱신은 이 한도에 걸리지 않습니다.

  • 포트를 다른 프로그램이 쓰는 경우 — 이 PC의 IIS 등이 443 · 80을 쓰고 있으면 다른 번호로 바꾸고, 공유기 포워딩도 그 번호로 맞추세요.

7서버 관리(관리자 콘솔) 서버 운영자

서버 전체를 다루는 화면입니다. 팀 소유자 · 관리자 같은 팀 등급과는 별개로, 서버 운영자에게만 보입니다.

여는 곳

앱 오른쪽 위 ☰ › 서버 관리(휴대폰은 더보기 탭)를 누릅니다. 탭은 운영 현황 · 회원 · 팀 · 감사 로그 · FCM 설정 · DDNS · 이모티콘입니다.

운영 현황

회원 · 팀 · 대화방 · 전체 메시지 수, 오늘 올라온 메시지와 댓글, 첨부파일 용량, 서버 시작 시각을 보여 줍니다. 서버 전체 설정도 여기서 정합니다.

설정설명
팀 생성 권한팀을 새로 만들 수 있는 최소 등급(정회원 · 관리자 · 서버 운영자). 준회원은 어느 경우에도 만들 수 없습니다.
팀 초대 링크 생성 권한팀 초대 링크(가입하면 팀에 자동으로 들어가고 등급도 받는 링크)를 만들 수 있는 최소 등급. 처음 설정은 관리자 이상입니다.
프로젝트 생성 권한프로젝트를 만들 수 있는 최소 등급.
팀 · 직책 관리부서 · 직책을 팀마다 따로 둘지(팀 단위), 계정 하나로 둘지(계정 단위) 정합니다. 계정 단위면 아래에서 직책 목록도 관리합니다.

회원 · 팀 · 감사 로그

탭할 수 있는 일
회원전체 회원을 이름 · 아이디로 찾고 상태와 소속 팀을 봅니다. 계정 등급 변경(준회원 · 정회원 · 관리자 — 등급은 여기서만 바꿉니다), 직책 수정, 계정 정지 · 해제, 모든 기기에서 로그아웃(휴대폰을 잃어버렸을 때), 서버 운영자 지정 · 해제를 합니다. 마지막 남은 서버 운영자는 해제 · 정지할 수 없으니 다른 사람을 먼저 운영자로 지정하세요.
팀서버의 모든 팀(내가 속하지 않은 팀 포함)의 이름 · 인원 · 만든 사람 · 만든 날을 봅니다. 팀 설정 변경과 삭제는 그 팀의 소유자가 합니다.
감사 로그관리자 권한으로 한 일(남의 메시지 삭제, 팀원 추가 · 제외, 등급 변경, 계정 정지, 서버 설정 변경 등)의 기록입니다. 종류로 걸러 볼 수 있습니다.

비밀번호를 대신 바꿔 주는 기능은 없어요

운영자가 남의 비밀번호를 정할 수 있으면 그 계정을 마음대로 쓸 수 있게 되므로 일부러 넣지 않았습니다. 비밀번호를 잊은 사람은 로그인 화면의 비밀번호 찾기로 직접 바꿉니다. 계정이 걱정되면 계정 정지나 모든 기기에서 로그아웃으로 대응하세요.

FCM 설정(휴대폰 알림)

안드로이드 앱의 푸시 알림(앱이 꺼져 있을 때 오는 알림)은 구글 Firebase(FCM)를 씁니다. 설정하지 않아도 메신저는 정상 동작하고, 앱이 켜져 있는 동안의 알림도 옵니다.

  1. Firebase 콘솔(console.firebase.google.com)에서 프로젝트를 만들고 안드로이드 앱을 추가합니다. 패키지 이름에 정확히 com.teamtalk.messenger를 넣습니다(다르면 알림이 오지 않습니다).

  2. 프로젝트 설정 › 일반에서 google-services.json을 받고, FCM 설정 탭의 google-services.json 열기로 고릅니다.

  3. 프로젝트 설정 › 서비스 계정 › 새 비공개 키 생성으로 받은 JSON 파일을 서비스 계정 JSON 열기로 고릅니다.

  4. 저장을 누릅니다. 서비스 계정: 설정됨이 보이면 끝이고, 서버를 다시 시작할 필요 없이 바로 반영됩니다. 받은 JSON 파일은 반드시 지우세요(서비스 계정 키는 비밀값입니다).

PC 앱을 켜 두면 휴대폰 알림이 안 온다면

환경설정 › 메신저 설정의 다른 기기 접속 중에도 휴대폰 알림 받기가 꺼져 있으면, PC 앱이 켜져 있는 동안 휴대폰 푸시를 보내지 않습니다. 처음 설정은 켜져 있습니다(메신저 이용법 › 메신저 설정). 아이폰 웹 앱은 FCM 없이 따로 설정할 것이 없습니다.

DDNS

위쪽은 DuckDNS 자동 갱신 설정과 상태(5장), 아래쪽은 웹 앱 주소(정식 인증서) 카드입니다. 인증서 카드는 보기만 하는 곳으로, 꺼짐(켜는 방법) · 발급 중 · 사용 중(도메인 · 만료일 · 아이폰 사용자에게 알려 줄 주소) · 곧 만료 · 발급 실패(이유와 다음 시도 시각)를 보여 줍니다. 켜고 끄는 것은 서버 PC의 시작 메뉴에서 합니다(6장).

백업

서버 전체(데이터베이스 · 서버 설정 · 인증서, 외부 백업 위치를 정하면 첨부파일까지)를 매일 정한 시각에 자동으로 백업합니다. 서버가 꺼져 있어 백업을 놓쳤으면 서버를 켜고 10분쯤 뒤에 한 번 합니다.

  1. 암호 정하기로 백업 암호(8자 이상)를 정합니다. 본인 확인을 위해 내 로그인 비밀번호도 한 번 더 넣습니다. 암호를 정해야 백업이 시작됩니다.

  2. 외부 백업 위치에 외장 드라이브(예: E:\TangoTalk백업)나 NAS 공유 폴더(예: \\NAS\backup)를 넣고 확인 후 저장을 누릅니다. 서버가 그 위치에 실제로 쓸 수 있는지 확인한 뒤 저장하고, 그 안에 TangoTalk-Backup 폴더를 만들어 씁니다.

  3. 필요하면 백업 시각(기본 새벽 3시)과 보관 개수(기본 최근 14개)를 바꾸고 저장합니다.

  4. 지금 백업으로 한 번 해 보고, 상태 카드가 정상이 되는지 확인합니다. 첨부파일이 많으면 첫 백업은 오래 걸리고, 다음부터는 바뀐 파일만 보냅니다.

상태 카드는 마지막 백업 시각 · 크기, 외부 위치 복사 결과, 다음 자동 백업 시각을 보여 줍니다. 외부 위치에만 실패하면(드라이브가 빠짐 · NAS가 꺼짐) 일부 실패로 보이고 서버 PC에는 백업이 남습니다. 외부 위치를 정하지 않았거나 서버와 같은 드라이브면 노란 경고가 뜹니다 — 디스크가 고장 나면 함께 사라지기 때문입니다.

NAS 공유 폴더를 쓸 때

NAS 경로(\\…)는 보안상 서버 PC에서 연 관리자 콘솔에서만 정할 수 있습니다(외장 드라이브 경로는 어디서든 됩니다). 서버는 Windows 서비스(이 PC의 컴퓨터 계정)로 NAS에 접속하므로, NAS에서 이 PC가 쓸 수 있게 공유 폴더 권한을 열어 두어야 합니다. "쓰지 못했습니다"가 나오면 외장 드라이브를 쓰는 편이 간단합니다.

되돌리기는 서버 PC의 시작 메뉴 복원에서 합니다(2장).

이모티콘

모든 사람이 쓸 수 있는 그림 이모티콘 세트와, 프로필 사진으로 고르는 캐릭터 세트를 만듭니다. 위쪽에서 이모티콘 · 캐릭터를 고르고 새 세트로 세트를 만든 뒤 그림을 올립니다. 세트의 대표 그림에 마우스를 올리면 그림 올리기 · 이름 바꾸기 · 세트 숨기기 · 개별 삭제 · 세트 삭제가 나옵니다. 올린 그림은 앱을 다시 배포하지 않아도 모든 사람에게 바로 보입니다. 세트 모음에서 그림을 누르면 숨기거나 다시 보이게 합니다(숨긴 그림은 선택창에서만 빠집니다).

개별 삭제를 고르면 그 세트의 모음이 고르기 상태로 열립니다. 지울 그림을 누르고(전체 선택도 됩니다) 삭제를 누르면 고른 그림이 이모티콘 선택창(캐릭터는 "캐릭터 선택하기")과 이 목록에서 한 번에 사라집니다. 이미 보낸 메시지의 이모티콘과 이미 프로필 사진으로 고른 캐릭터는 그대로 보입니다. 그만두려면 취소.

운영자를 모두 잃었을 때

서버 운영자가 모두 탈퇴 · 정지되어 아무도 서버 관리에 들어갈 수 없다면, 서버 PC에서 이미 가입한 계정 하나를 운영자로 되돌립니다.

  1. 탐색기로 설치 폴더(기본 C:\TangoTalk-Server)를 엽니다.

  2. Grant-ServerAdmin.ps1을 오른쪽 클릭 › PowerShell에서 실행을 누릅니다(Windows 11은 더 많은 옵션 표시 안에 있습니다). 관리자 권한 확인 창에서 예를 누릅니다.

  3. 운영자로 지정할 계정의 아이디를 넣습니다. 정지되어 있던 계정이면 정지도 풀립니다.

  4. 그 사람이 앱을 다시 시작하면 서버 관리가 보입니다.

활성 서버 운영자가 한 명이라도 있으면 아무것도 바꾸지 않습니다. 그때는 그 운영자가 관리자 콘솔에서 지정하세요.

8문제가 생겼을 때

서버 오류 기록(로그)은 어디서 보나요?

서비스로 설치했다면 설치 폴더\server\service-err.log(오류)와 service-out.log(일반 기록)입니다. 메모장을 관리자 권한으로 실행해 엽니다. 이 파일은 계속 이어서 쌓이므로 맨 아래쪽이 가장 최근 기록입니다. 서버 재시작 뒤 서버가 뜨지 않으면 그 창에서 바로 열 수도 있습니다.

서버 업데이트 중 "npm install 실패"가 나와요.

같은 폴더에 서버 프로그램을 다시 설치하면서 예전 부품 파일이 섞였을 수 있습니다. 관리자 권한 PowerShell에서 서버를 멈추고 설치 폴더\node와 설치 폴더\server\node_modules 두 폴더만 지운 뒤(데이터는 다른 폴더에 있습니다), 설치 프로그램을 같은 경로로 다시 실행하고 서버 업데이트를 같은 zip으로 다시 하세요. 최신 설치 프로그램은 다시 설치할 때 이 두 폴더를 스스로 새로 바꿉니다.

초대 링크를 밖에서 열면 "유효하지 않은 초대 링크입니다"가 나와요.

링크를 만든 서버가 아닌 다른 PC가 응답하고 있다는 뜻입니다. 공유기에서 초대 안내 페이지 포트(기본 3001)가 이 서버 PC로 가는지 확인하세요. 서버가 둘(개발용 · 운영용)이면 포트가 엇갈리기 쉽습니다. 연결 자체가 안 되면 그 포트가 아예 열려 있지 않은 것입니다.

밖에서 앱이 연결되지 않아요.

① 외부 접속 주소가 들어가 있는지(4장), ② 공유기 포트포워딩이 서버 PC의 지금 사내 IP로 가는지, ③ 외부 포트가 서버 포트와 다른데 주소에 :포트를 빠뜨리지 않았는지, ④ DDNS 이름이 지금 공인 IP를 가리키는지(DDNS 탭)를 차례로 보세요. 사용하는 사람은 회사 와이파이에서 앱을 한 번 켜 두어야 외부 주소를 받아 둡니다.

안드로이드에 푸시 알림이 오지 않아요.

① FCM 설정 탭에 서비스 계정이 설정됨인지, ② 받는 사람이 PC 앱도 켜 두었다면 다른 기기 접속 중에도 휴대폰 알림 받기가 켜져 있는지, ③ 앱을 열어 둔 채 시험하지 않았는지(앱이 연결돼 있으면 푸시 대신 앱 안의 알림으로 받습니다), ④ 휴대폰에서 앱을 "강제 중지"하지 않았는지 (강제 중지한 앱에는 다시 열 때까지 알림이 오지 않습니다), ⑤ 앱의 알림 권한과 배터리 설정("제한 없음")을 확인하세요.

아이폰 웹 앱이 "안전하지 않음"으로 열려요.

정식 인증서가 아직 없거나 시험용 인증서인 상태입니다. DDNS 탭의 웹 앱 주소 카드에서 상태를 보고, 시험 발급이 켜져 있으면 끄고 다시 적용하세요(6장).
