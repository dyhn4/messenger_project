TangoTalk 서버 설치가 끝났습니다.

■ 이미 쓰던 서버에 새 버전을 적용할 때 꼭 알아 둘 것
  - 시작 메뉴 "서버 업데이트"(업데이트 zip)는 서버 코드만 바꿉니다. 설치 폴더 보안 잠금(아래 "설치 폴더 보안"), 시작 메뉴의
    관리 도구(설치 폴더의 *.ps1 — 백업·복원·페어링 코드 발급 등)와 이 안내문은 zip으로는 바뀌지 않습니다.
  - 그래서 설치 폴더 잠금이 생기기 전 버전으로 설치한 서버는, 이 버전의 설치 프로그램(tangotalk-server-setup.exe)을 같은
    설치 경로로 한 번 다시 실행해야 설치 폴더가 관리자 전용으로 잠깁니다(.env·DB·첨부파일·인증서는 그대로 이어집니다).
    그 뒤로는 "서버 업데이트"가 업데이트할 때마다 잠금을 다시 맞춥니다.
  - 확인 방법: 설치 폴더(기본 C:\TangoTalk-Server)에 Folder-Acl.ps1이 없으면 아직 잠금 전 버전입니다 — 설치 프로그램을
    다시 실행하세요. 앞으로도 설치 프로그램 쪽(관리 도구·설치 과정)이 바뀐 버전이 나오면 설치 프로그램을 다시 실행합니다.
  - 이 버전에서 설치 프로그램을 다시 실행해야 고쳐지는 것: 서버 운영자 비밀번호에 한글 등 영문·숫자·기호가 아닌 글자가 있으면
    "복원"·"DB 데이터 초기화"·"서버 완전 삭제"의 운영자 확인이 맞게 쳐도 늘 실패하던 문제, 서버 오류 응답에 서버 안의 파일
    경로가 보일 수 있던 문제(서버를 운영 모드로 실행).
  - 이 버전에서 설치 프로그램을 다시 실행해야 생기는 것: 시작 메뉴 "웹 앱 주소(정식 인증서)"(아이폰 웹 앱용 — 아래 "아이폰(웹 앱)으로
    접속하게 하려면").

■ 서버 상태 확인
  - 브라우저에서 https://localhost:3000/health 접속 → {"ok":true}가 보이면 정상입니다.
  - 인증서가 자체 서명이라 브라우저가 경고를 띄울 수 있습니다 — "고급" → "이동" 등으로 넘어가면 됩니다.

■ 새 기기(클라이언트 앱) 연결하기
  1. 시작 메뉴 "TangoTalk Server" 그룹의 "새 기기 페어링 코드 발급"을 실행하면 4자리 코드가 뜹니다(5분간 유효, 1회용).
     서버 포트 설정(.env)을 읽어야 해서 관리자 권한 확인 창이 먼저 뜹니다 — "예"를 누르세요.
  2. 클라이언트 앱의 "서버 주소 변경" 화면에서 이 PC의 주소(예: https://192.168.0.10:3000)와 그 코드를 함께 입력하세요.

■ 아이폰(웹 앱)으로 접속하게 하려면 — 정식 인증서 (선택 사항)
  - 아이폰은 앱 대신 사파리에서 웹 앱을 씁니다. 사파리에서 경고 없이 열고 "홈 화면에 추가"·알림(웹 푸시)까지 쓰려면 공인 인증서가
    필요해서, 도메인을 정해 두면 서버가 Let's Encrypt 인증서를 스스로 받고 갱신해 웹 전용 HTTPS 포트(기본 443)로 웹 앱을 엽니다.
    PC·안드로이드 앱은 지금처럼 메인 포트(3000)와 기존 인증서를 그대로 쓰므로 다시 페어링할 필요가 없습니다.
  1. 공유기에서 DDNS를 켜 둡니다(예: xxx.iptime.org — "외부 접속 주소"에 쓰는 이름과 같아도 됩니다).
  2. 시작 메뉴 "웹 앱 주소(정식 인증서)"를 열고(관리자 권한 확인 창에서 "예") 도메인, 웹 HTTPS 포트(기본 443), 인증용 HTTP 포트
     (기본 80, 0이면 안 씀), 이메일(선택)을 넣은 뒤 "적용"을 누릅니다 — .env 저장, 이 PC의 방화벽 규칙, 서버 재시작까지 해 줍니다.
     이 PC에서 IIS 등이 443·80을 이미 쓰고 있거나 도메인을 DNS에서 찾을 수 없으면 적용 전에 알려 줍니다 — 포트가 겹치면 다른
     번호(예: 8443·8080)를 고르고 아래 포워딩을 그 번호로 하세요.
  3. 공유기 포트포워딩(iptime: 고급 설정 → NAT/라우터 관리 → 포트포워드 설정):
       외부 TCP 443 → 이 PC의 웹 HTTPS 포트, 외부 TCP 80 → 이 PC의 인증용 HTTP 포트
     웹 HTTPS 포트를 443이 아닌 번호로 했다면 외부의 그 번호도 이 PC의 같은 번호로 엽니다(아이폰이 여는 주소에 그 번호가 붙습니다).
     통신사가 80을 막아도 443으로 인증서를 받을 수 있습니다. 이 PC의 방화벽은 2번의 "적용"이 이미 열어 둡니다.
  4. 1~2분 뒤 같은 창의 "인증서 확인"이나 앱의 관리자 콘솔에서 발급 상태를 확인합니다. 실패하면 서버가 간격을 두고(1시간부터 점점
     늘려 최대 하루) 알아서 다시 시도합니다 — 서버를 다시 시작해도 그 시각 전에는 다시 묻지 않으니, 실패 이유와 다음 시도 시각은
     관리자 콘솔에서 보세요.
  5. 아이폰 사용자: 사파리에서 https://도메인(443이 아니면 https://도메인:포트)을 열어 로그인 → 공유 버튼 → "홈 화면에 추가".
     알림은 홈 화면에 추가한 아이콘으로 연 앱에서 켭니다(iOS 16.4 이상).
  - iptime.org 주의: Let's Encrypt는 iptime.org 아래 이름을 모두 도메인 하나로 세서, 모든 iptime DDNS 사용자가 "같은 도메인 7일에
    새 인증서 50개" 한도를 함께 씁니다. 그래서 첫 발급이 한도 초과(rateLimited)로 실패할 수 있습니다 — 서버가 Let's Encrypt가 알려 준
    시각(몇 시간~며칠 뒤)에 다시 시도하니 기다리거나, 회사 도메인의 하위 이름(예: chat.회사도메인)을 CNAME으로 DDNS 이름에 연결하고
    그 이름을 넣으세요(도메인을 바꾸면 바로 다시 시도합니다). 한 번 받은 인증서의 갱신은 이 한도에 걸리지 않습니다.
  - 포트포워딩이 맞는지 먼저 확인하려면 "시험 발급"을 켜고 적용하세요(정식 발급 한도를 쓰지 않는 시험용 인증서 — 아이폰에서는 못
    씁니다). "인증서 확인"에 시험용 인증서가 보이면 "시험 발급"을 끄고 다시 적용합니다(그러면 바로 정식 인증서를 받으러 갑니다).
  - 끄려면 같은 창의 "끄기"(이 PC의 방화벽 규칙도 지웁니다). 공유기의 443·80 포트포워딩도 지우세요.

■ 푸시 알림(FCM)을 쓰고 싶다면 (선택 사항 — 안 해도 서버는 정상 작동합니다)
  Firebase 콘솔에서 발급받은 서비스 계정 키 파일을 아래 경로에 그대로 복사하세요:
    <이 설치 폴더>\server\firebase-service-account.json
  설치 폴더는 관리자 전용이라(아래 "설치 폴더 보안") 탐색기가 "관리자 권한이 필요합니다" 창을 띄우면 "계속"을 누르세요.
  복사한 뒤에는 서버를 재시작해야 반영됩니다(서비스 모드라면 서비스 재시작, 콘솔 모드라면 창을 닫았다가 다시 실행).

■ 서버를 껐다 켜고 싶다면
  - 서비스 모드로 설치했다면: Windows "서비스" 관리 도구(services.msc)에서 "TangoTalkServer"를 시작/중지하세요.
  - 콘솔 모드로 설치했다면: 시작 메뉴의 "서버 콘솔로 실행"으로 실행하고(관리자 권한 확인 창이 뜹니다), 끌 때는 그 창을 닫으면 됩니다.

■ 설치 폴더 보안(관리자 전용)
  - 설치 폴더에는 DB 비밀번호·암호화 키·인증서 개인키·백업 같은 비밀값이 들어 있고, 서버(TangoTalkServer)와
    화상회의(TangoTalkLiveKit) 서비스는 LocalSystem 계정, PostgreSQL은 NetworkService 계정으로 실행됩니다.
    그래서 이 폴더는 SYSTEM과 관리자(Administrators)만 열고 고칠 수 있게 잠겨 있습니다 — 다른 계정은 시작 메뉴
    바로가기와 이 안내문만 열 수 있습니다.
  - .env를 직접 고치거나 로그(install.log, server\service-err.log 등)를 보려면 메모장을 "관리자 권한으로 실행"한 뒤
    [파일 → 열기]로 여세요. .env를 고친 뒤에는 시작 메뉴 "서버 재시작"(재시작 뒤 서버가 정상이 아니면 그 창에서
    service-err.log를 바로 열 수 있습니다).
  - 시작 메뉴의 관리 도구(페어링 코드 발급·서버 업데이트·재시작·첨부파일 저장소·외부 접속 주소·웹 앱 주소(정식 인증서)·백업·복원·
    DB 데이터 초기화·완전 삭제)는 실행할 때마다 관리자 권한 확인 창이 뜹니다.
  - 설치 프로그램을 다시 실행하거나 "서버 업데이트"를 할 때마다 이 권한을 다시 맞춥니다.
  - 첨부파일 저장소를 설치 폴더 밖 다른 로컬 폴더로 옮기면("첨부파일 저장소") 그 폴더도 같은 방식으로 잠급니다.
    NAS/공유 폴더는 이 PC가 잠글 수 없으니 NAS 설정에서 이 서버 PC만 접근하게 제한하세요.

■ 백업
  - 앱의 "서버 관리 › 백업" 탭에서 백업 암호를 정하면 서버가 매일(기본 새벽 3시) DB·서버 설정·인증서를 백업 암호로 암호화해
    <이 설치 폴더>\backups\tangotalk_<날짜>_<시각>\에 백업합니다(최근 14개 보관 — 바꿀 수 있음). 같은 탭에서 외장 드라이브나
    NAS를 "외부 백업 위치"로 정하면 그곳에도 복사하고 첨부파일까지 맞춰 둡니다 — 이 PC가 고장 나도 새 PC에서 되살릴 수 있게
    꼭 정해 두세요.
  - 백업 암호를 잃어버리면 백업을 복원할 수 없습니다. 이 PC가 아닌 안전한 곳에 적어 두세요.
  - 시작 메뉴 "백업"은 같은 전체 백업을 지금 한 번 더 합니다(백업 암호를 아직 정하지 않았으면 예전처럼 DB만 .dump로 저장 —
    가장 최근 10개만 남김). "복원"은 백업 폴더 안의 manifest.json(또는 예전 .dump)을 골라 되돌립니다.
  - 이 PC가 고장 났으면: 새 PC에 서버를 설치하고(가입하지 말고) 외장 드라이브·NAS를 연결한 뒤 "복원"에서
    TangoTalk-Backup\tangotalk_<날짜>_<시각>\manifest.json을 고르면 회원·대화·설정·인증서·첨부파일이 돌아옵니다.
  - 예전 방식의 .dump 백업은 암호화돼 있지 않고 회원 비밀번호 해시 등 모든 데이터가 들어 있습니다. 다른 곳에 복사해 둘 때도
    아무나 열 수 없는 곳에 두세요.
  - 백업 폴더를 관리자 전용으로 안전하게 잠글 수 없으면(폴더가 링크로 바뀌어 있거나, 예전 버전으로 설치된 경우 등)
    백업이 "안전을 위해 백업하지 않습니다"라며 멈춥니다 — 이때는 최신 서버 설치 프로그램(tangotalk-server-setup.exe)을
    한 번 다시 실행한 뒤 백업하세요.

■ 서버를 제거했다가 다시 설치할 때
  - 시작 메뉴 "TangoTalk 서버 제거"(= Windows "설치된 앱"에서 제거)는 프로그램 파일만 지우고, DB(pgsql-data)·비밀값(secrets)·
    .env·첨부파일·인증서·백업은 설치 폴더에 그대로 남깁니다. 같은 설치 경로로 다시 설치하면 그 데이터를 그대로 이어서 씁니다.
  - 설치 폴더 잠금이 생기기 전 버전으로 설치했다가 제거한 폴더에 다시 설치하면 "다른 Windows 계정도 이 폴더에 파일을 넣거나
    폴더 이름을 바꿀 수 있게 권한이 열려 있습니다"라는 확인 창이 뜹니다. 이 PC에서 직접 설치했다가 제거한 바로 그 폴더가
    확실할 때만 "예"를 누르세요(설치가 끝나면 관리자 전용으로 잠기고, 그 뒤로는 이 창이 뜨지 않습니다). 확실하지 않으면
    "아니요"를 누르고 아래처럼 폴더 내용부터 확인하세요.
  - "서버 완전 삭제"는 DB·첨부파일·인증서·.env·비밀값까지 지우고 백업 폴더(backups)·로그 등은 남깁니다(창에 남는 것을 보여 줍니다).
    같은 경로에 다시 설치하면 빈 서버로 새로 시작합니다. 전체 백업(tangotalk_<날짜>_<시각>)에는 암호화 키가 들어 있어 백업 암호만
    있으면 됩니다. 예전 .dump 백업을 나중에 "복원"할 생각이면 완전 삭제 "전에" server\.db-encryption-key를 안전한 곳에
    복사해 두세요 — 이 키가 없으면 복원한 데이터 속 암호화된 이메일 등을 읽을 수 없습니다.
  - 설치 프로그램이 "이전 TangoTalk 서버 설치나 이 PC의 관리자 권한으로 만든 폴더인지 확인되지 않았습니다" 또는 "다른 계정도
    파일을 넣거나 이름을 바꿀 수 있는 폴더라서"라며 멈추면 그 폴더를 바로 지우지 마세요 — 예전 서버의 DB·비밀값·백업이 들어
    있을 수 있습니다. 먼저 내용을 확인하고 필요한 것을 안전한 곳에 옮긴 뒤, 다른 설치 경로(새 폴더)를 골라 설치하세요.

■ 서버 운영자 계정을 잃어버렸을 때(아무도 관리자 콘솔에 들어갈 수 없을 때)
  - 서버 운영자가 모두 탈퇴·정지되거나 운영자 지정이 풀려 아무도 운영자로 로그인할 수 없으면, 이 서버 PC에서 이미 가입한
    계정 하나를 다시 서버 운영자로 지정할 수 있습니다(정지돼 있던 계정이면 정지도 풀립니다). 활성 서버 운영자가 한 명이라도
    있으면 아무것도 바꾸지 않습니다 — 그때는 그 운영자가 앱의 관리자 콘솔에서 지정하세요.
  - 방법: 탐색기로 설치 폴더(기본 C:\TangoTalk-Server)를 열고 Grant-ServerAdmin.ps1을 오른쪽 클릭 → "PowerShell에서 실행"
    (Windows 11은 "더 많은 옵션 표시" 안에 있음) → 관리자 권한 확인 창에서 "예" → 운영자로 지정할 계정의 아이디를 입력합니다.
    (관리자 권한 PowerShell에서 powershell -ExecutionPolicy Bypass -File "C:\TangoTalk-Server\Grant-ServerAdmin.ps1" 로 실행해도 됩니다.)
  - 끝나면 그 계정으로 로그인해 관리자 콘솔을 쓸 수 있습니다(이미 로그인해 있었다면 앱을 다시 시작하세요).
